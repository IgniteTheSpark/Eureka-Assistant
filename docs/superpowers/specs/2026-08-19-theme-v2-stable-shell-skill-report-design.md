# Theme V2 稳定 Shell、技能管理与报告范围校准设计

日期：2026-08-19

## 目标

本轮修复五个已经在真机上暴露的问题，并保持首页当前的核心设计语言：

1. 全局页面恢复纯色背景，仅首页的「Reka 发现」和「Reka 生成」两个容器保留 dither。
2. 自定义 Skill 的字段、展示和删除收敛到一个管理入口。
3. 页面切换不再让 Reka 短暂退回 2D fallback。
4. 页面切换或普通路由返回不再让资产库冷启动、长时间刷新或白屏。
5. 报告输入能从“总结最近的跑步情况”中准确识别跑步资产，并要求用户确认“最近”的时间范围。

## 已确认方案

采用方案 A：修复共享 Shell 的生命周期根因，并在此基础上收敛技能管理、数据刷新和报告范围选择。不采用给 Reka 加遮罩、给资产库单独堆缓存的局部补丁，也不在本轮重构成三个独立 Navigator。

## 根因

### Reka 首帧与资产库冷启动

`ThemeV2AppShell` 把同一个 `IndexedStack` 放进当前页面的 `ThemeV2PageScaffold`。首页使用沉浸式 Stack 布局，日历和资产库使用普通 Column 布局。切换 Tab 时，`IndexedStack` 在两棵不同的组件树之间迁移，Flutter 会销毁并重新创建其子页面。

这会同时造成：

- Reka 的 WebView 和 WebGL renderer 重新启动，ready 之前先显示 2D fallback；
- 资产库的 controller、缓存和滚动状态重新创建，重新请求网络；
- 网络请求较慢时，用户看到冷启动 loading 或纯白过渡。

### 资产库的额外刷新

全局 `DataRefreshObserver` 在任何 route pop 时都会增加 `dataRevision`。资产库同时监听该 revision，所以即使离开的页面没有修改资产，返回时也会刷新。真实数据变更与普通导航返回没有被区分。

### 报告类型误选

报告范围适配器目前只针对消费类关键词做资产类型过滤。意图包含“跑步”时无法命中任何硬编码规则，于是回退为全部可聚合 Skill，导致跑步、消费、喝水和跳舞同时默认选中。

“最近”在后端草稿中已经可以保持为未解析时间，但这条状态必须通过候选接口和移动端确认页完整保留，不能被 30 天预览窗口误当成已确认范围。

## 设计

### 1. 稳定的应用 Shell

`ThemeV2PageScaffold` 使用一套稳定的 Stack 组合，不再根据 `extendBodyBehindChrome` 在两种不同的组件树之间切换。页面主体始终位于同一个 child slot，顶部导航、底部 Dock 和内容避让通过布局参数计算。

`ThemeV2AppShell` 中的 `IndexedStack` 在整个 Shell 生命周期内保持相同元素身份。切换 Tab 只改变 active index、导航栏可见性和内容 inset，不卸载三张根页面。

结果：

- Reka WebView 只在首页首次建立时初始化；
- 返回首页直接显示上一次的 3D renderer，不经过 fallback；
- 资产库 controller、已加载数据、当前子容器和滚动位置继续存在；
- 日历现有状态也一并受益，但不改变其业务行为。

应用进入后台时仍允许暂停动画和 WebGL；本轮只保证 App 内 Tab 切换不会重建 Reka。

### 2. Dither 范围与首页空容器

移除 `ThemeV2PageScaffold` 的全局 `ThemeV2DitherSurface`。日历、资产库、报告页、顶部导航和底部 Dock 使用主题的纯色背景与既有 surface 层级。

首页保留两个局部 dither 容器：

- 上方「Reka 发现」信号容器；
- 下方「Reka 生成」资产容器。

两个容器无论是否有内容都持续存在并显示水印，让用户能够理解页面结构和内容归属。空态不新增说明文案或边框。

水印调整原则：

- 标签和数量整体提升一个视觉层级，字号与字重明显高于当前版本；
- 浅色和深色模式都达到稳定可读，不再依赖 dither 纹理衬托；
- 水印仍位于背景层，透明度低于资产球和信号条，内容经过时不抢焦点；
- 「Reka 发现」与「Reka 生成」继续在中轴两侧错开并保持对称间距；
- 无内容时数量显示为 0，标签仍可点击进入信号列表或资产库。

首页两个容器的 dither 实现和内容挤压效果保留，Reka 自身不增加 dither 背景。

### 3. Skill 管理入口

#### 自定义 Skill

资产容器顶部只保留一个「管理 Skill」入口。管理页按以下顺序展示：

1. 基本信息：名称和说明；
2. 记录字段：字段展示名、含义、顺序、显示/隐藏及添加选填字段；
3. 卡片展示：卡片预览、主字段和最多三个次字段；
4. 危险操作：删除 Skill 与其记录。

保存动作统一提交字段配置和卡片展示配置。若其中一部分失败，页面保留用户输入并明确显示失败位置，不静默关闭。

#### 内置 Skill

内置 Skill 不允许修改 schema 或删除，因此只保留「卡片展示」入口。

独立卡片展示页不显示 `Describe / Fields / Card` stepper。该 stepper 只属于“创建新 Skill”的三步向导，创建流程保持不变。

### 4. 资产库刷新策略

引入“真实数据变更”和“普通导航返回”的区分：

- 创建、编辑、删除资产或 Skill 时发布数据变更 revision；
- 普通 route pop、打开后未修改直接返回、Tab 切换不发布资产库变更；
- App resume 可以请求轻量刷新，但不得清空现有资产库内容。

资产库采用 stale-while-revalidate：

- 首次进入且没有缓存时显示 skeleton/loading；
- 已有内容时，后台刷新只显示非阻塞的小型状态，不替换整页；
- 刷新失败时保留现有内容并显示可重试提示；
- 同一时刻只允许一个 overview 请求和一个当前容器请求；
- Tab 切换不会发起请求；
- 从资产详情返回时，只有发生真实修改才刷新。

### 5. 报告资产类型与时间确认

报告范围适配器从用户意图中匹配 Skill 时使用：

- Skill `display_name`，忽略“记录、日志、数据”等通用后缀；
- `machine_name` 的标准化词组；
- Skill 的描述和领域信息；
- 内置类型的少量稳定同义词，例如跑步/晨跑/running、消费/支出/expense。

匹配规则以明确命中为准：如果意图明确提到跑步，只返回跑步相关 Skill；没有明确类型时才展示全部可汇总 Skill。不会仅因多个 Skill 都属于健康领域就一起选中。

对于“最近”这类未给出具体天数的时间词：

- scope draft 的 `time_range` 保持为空；
- `missing_dimensions` 包含 `time_range`；
- 可以使用内部 30 天窗口预取候选数据，但该窗口不写入默认选择，也不表示用户已经确认；
- 移动端先展示过去 7 天、过去 30 天、本周、本月和自定义时间；
- 用户确认时间后，才默认全选该范围内匹配类型的资产；
- 用户仍可手动补充其他资产。

因此“总结最近的跑步情况”的默认状态是：资产类型只有跑步，时间未确认，资产记录尚未自动选中。

## 错误与降级

- Shell 状态保持失败不得回退为每次重建页面；应通过测试阻止该结构回归。
- Reka WebGL 在真正的 context loss 或初始化失败时仍可使用 2D fallback。
- 资产库首次加载失败显示错误页；已有缓存时失败只显示局部提示。
- Skill 管理页加载卡片配置失败时仍允许查看基本信息，但禁用统一保存并提供重试。
- 报告类型无法可靠匹配时展示全部候选供用户选择，不做不可见的猜测。

## 测试与验收

### 自动化测试

- Shell：连续切换首页、日历、资产库后，三个根页面的 State identity 不变。
- Reka：离开并返回首页时 renderer widget 不重新创建，不出现 loading/fallback 状态重置。
- 资产库：Tab 切换不增加 repository load 次数；普通 route pop 不刷新；真实 mutation 触发一次后台刷新并保留内容。
- Dither：普通页面 scaffold 中没有全局 dither；首页恰好保留两个容器 dither。
- 首页空态：发现数和生成数为 0 时，两处水印仍存在、可读且可点击。
- Skill：自定义容器只有一个管理入口；管理页包含字段和卡片展示；配置模式无 stepper；创建模式仍有三步 stepper。
- 报告：“总结最近的跑步情况”只返回跑步 group，`time_range` 为空且标记待确认；明确“过去 30 天”时自动选中对应跑步资产。

### 真机验收

使用包含 `THEME_V2=true` 与 `TODAY_DOT_EXPERIMENT=true` 的 Debug APK：

1. 首页与日历、资产库来回切换至少五次，Reka 不出现扁平 fallback。
2. 资产库内容和滚动位置保持，不出现白屏或重复机械刷新。
3. 日历、资产库和全局导航均为纯色背景，首页两个容器仍有 dither。
4. 清空或使用无信号、无资产账号时，两个容器的 0 数量水印仍清晰可见并可点击。
5. 自定义 Skill 只有一个管理入口，能在同一页调整字段与卡片展示。
6. 发起“总结最近的跑步情况”，只看到跑步类型，并必须先确认时间范围。

## 本轮不做

- 不取消首页两个容器的 dither 或重新设计其物理效果。
- 不改变 Reka 的 3D 模型、眼睛、产出动画或拖动手势。
- 不把三个 Tab 改造成独立 Navigator。
- 不重新设计报告方案生成及最终报告版式。
- 不改变内置 Skill 的可编辑权限。
