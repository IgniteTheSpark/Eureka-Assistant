# Eureka Ring Spline 桌面端运动编排设计

**日期：** 2026-07-21
**状态：** 已确认，待实施
**范围：** `ring-demo` Landing Page 桌面端戒指展示；移动端适配不在本轮范围

## 1. 目标

用 Spline 取代当前由 React Three Fiber 手写的桌面端戒指运动编排，使产品团队可以在可视化三维场景中直接调整戒指的空间路线、停靠姿态、相机、灯光和缓动，同时保持原始建模文件的几何与 PBR 材质数据不被网页运行时代码二次改造。

本轮交付应满足：

- 使用设计师提供的原始 `戒指_7_17.glb`；
- 页面章节之间的主轨迹由页面滚动连续控制，向上滚动时严格倒放；
- Hero、Flash、Vibe 在关键展示位拥有短暂的自主入场动画；
- Flash 和 Vibe 使用磁悬浮捕获动作，不产生触底碰撞；
- “说、触、感”使用硬币式前后翻面；
- 第一阶段仅完成并验收桌面端 `1440 × 900`；
- Spline 视觉验收通过前，现有 Three.js 实现保留为开发期 A/B 对照路径。

## 2. 权威模型与校验结果

权威源文件：

```text
/Users/admin/硬件相关/录音戒指概念图/戒指_7_17.glb
```

仓库运行时副本：

```text
ring-demo/public/ring/ring-capacitive-7-17.glb
```

两份文件二进制一致：

```text
SHA-256 f3cb75b21724dbcfc02e9949747b850a7a577674aa527cc533ad15a805a5f6ce
```

GLB 结构检查结果：

- Blender glTF 导出器版本：`Khronos glTF Blender I/O v5.0.21`；
- 8 个网格节点；
- 6 个 PBR 材质：`材质`、`材质.001`、`材质.002`、`材质.003`、`材质.004`、`材质.005`；
- 1 个根节点 `空物体`；
- 无手部模型；
- 无嵌入相机；
- 无嵌入动画；
- 无 glTF 扩展。

因此 Spline 可以直接导入完整戒指，不需要删除节点、重建外壳、校正电路半径或细分曲面。

## 3. 模型保真边界

Spline 导入后必须遵守以下限制：

- 不编辑 8 个原始网格的顶点、拓扑、UV、法线和相对变换；
- 不执行 Boolean、Subdivision、Sculpt、Remesh 或自动降面；
- 不启用会降低几何精度的导出压缩；
- 不替换 6 个原始材质，不改其 base color、metalness、roughness 和 emissive 基础值；
- 不在戒指模型内部创建额外的外壳、电路或触控面；
- 暖橙、蓝紫、触控提示与连接反馈由外部灯光和效果层实现，不写回产品材质；
- 所有产品运动只施加在 GLB 外部的父级 Rig 上。

Spline 导入会使用自身的实时渲染器解释标准 PBR 数据，因此最终画面仍需要与 Blender/原始 GLB 参考图做视觉验收；“不改模型数据”不等同于不同渲染器间像素级一致。

## 4. 选定方案

使用单一 Spline Viewer 和 Spline Scroll Event。

不采用以下方案：

- React Code API 逐帧写入位置、旋转和缩放：会重新形成代码坐标难以调节的问题；
- Spline 只作为运动参考再把参数搬回 Three.js：后续每次改动都需要重复导出和转换；
- 多个 Spline Embed：会复制 GLB 和渲染上下文，增加内存和加载成本。

官网 React 继续负责内容、语言、章节布局、二维码和加载回退。Spline 只负责戒指、相机、灯光和运动。

## 5. Spline 场景结构

场景采用分层 Rig，避免主滚动、自主入场、漂浮和翻面互相覆盖：

```text
EurekaRingScene
├── JourneyRig
│   └── ShowcaseRig
│       └── FloatRig
│           └── FlipRig
│               └── OriginalRingGLB
├── CameraRig
│   └── ProductCamera
├── LightingRig
│   ├── KeyLight
│   ├── FillLight
│   └── RimLight
└── EffectsRig
    ├── FlashMagneticField
    ├── VibeMagneticField
    └── TouchLocalLight
```

各层职责：

- `JourneyRig`：整页 Scroll Scrub，负责章节之间的位置、基础旋转、尺度和可见性；
- `ShowcaseRig`：Hero、Flash、Vibe 的短暂自主入场动画；
- `FloatRig`：关键展示姿态稳定后的轻微上下漂浮；
- `FlipRig`：说、触、感章节的硬币式前后翻面；
- `CameraRig`：产品构图与轻度透视，不承载滚动状态；
- `LightingRig`：不随材质修改的三点产品光；
- `EffectsRig`：独立于模型的磁场扩散与局部提示光。

`OriginalRingGLB` 在 Spline 中锁定，避免误编辑。

## 6. 相机与灯光

由于源 GLB 不包含相机和灯光，Spline 场景负责产品摄影环境：

- 使用透视相机，初始 FOV 约 35°，减少广角形变；
- Hero 使用三分之四视角，优先展示外壳、内壁、电路和触控区的层次；
- Key、Fill、Rim 三盏主灯建立稳定的产品轮廓；
- 不增加第四盏常驻主灯；章节效果光按需短暂启用；
- 阴影保持柔和且克制，不用硬落地阴影暗示戒指碰撞容器底部；
- 不启用重型景深、粒子或全屏后处理。

## 7. 页面顺序与主滚动轨迹

最新页面顺序为：

1. Hero；
2. 双模式过渡；
3. Flash；
4. Vibe；
5. 说、触、感；
6. System；
7. Community CTA / Finale。

主轨迹必须是一条连续曲线。即使戒指在 Flash/Vibe 场景图交接时缩小或淡出，空间位置仍继续沿曲线移动，确保反向滚动时不会瞬移。

Spline Viewer 使用一个覆盖整页的 Scroll Event：

- Page Start 对应 Hero 起点；
- Page End 对应 Community CTA 最终姿态；
- 各章节状态按桌面页面的稳定高度分配时间区间；
- 中英文 Section 保持相同的结构和最小高度，避免切换语言后时间轴漂移；
- `data-ring-chapter` 锚点继续保留，作为页面结构、Three.js A/B 路径和测试的稳定标识；
- 桌面布局高度发生实质变化时，必须重新校准 Spline Scroll Event 的区间。

## 8. Hero 自主入场

Hero 仅在首次进入官网且 Hero 位于可视区域时播放一次产品亮相：

- 总时长约 1.6 秒；
- 起点略高于最终位置，尺度约为最终值的 88%；
- 围绕垂直轴旋转约 220°；
- 同时收束到最终三分之四产品角度；
- 使用平滑减速，不产生落地回弹；
- 完成后只保留约 `±6px`、周期约 4.2 秒的上下漂浮；
- 漂浮不叠加自动翻滚或永久自转。

刷新页面时如果浏览器恢复到非 Hero 的历史滚动位置，则跳过 Hero 入场，直接进入当前位置对应的稳定状态。

## 9. Flash 与 Vibe 磁悬浮捕获

Flash 和 Vibe 的展示槽采用相同的运动物理、相反的旋转方向：

- Flash 从容器上方落入右侧展示槽；
- Vibe 从容器上方落入左侧展示槽；
- 展示槽进入视口中心触发区时播放；
- 离开该板块后重置；重新进入可以再次播放；
- 设置触发迟滞区，避免边界处轻微滚动造成连续重播。

### 9.1 时间与位置曲线

磁悬浮捕获用时约 1.2 秒，随后追加约 1.4 秒的慢速产品旋转展示：

1. `0.00–0.42s`：戒指从展示舱上方快速进入；
2. `0.42–0.68s`：接近悬浮平衡面时被无形磁场明显减速；
3. 继续穿过平衡点约 14px，表达进入惯性，但不接触容器底部；
4. `0.68–0.90s`：向上回弹约 7px；
5. 再产生一次约 2px 的阻尼回摆；
6. `0.90–1.20s`：稳定在悬浮点；
7. `1.20–2.60s`：在悬浮状态下继续完成约 140° 的慢速产品旋转展示；
8. 展示旋转结束后停止持续自转，只保留轻微上下漂浮。

### 9.2 旋转与效果

- Flash 捕获过程中旋转约 `+110°`；
- Vibe 捕获过程中旋转约 `-110°`；
- 捕获稳定后，两者各自追加一次约 140° 的慢速产品旋转，用于展示外壳、内壁、电路与触控区；
- 磁场触发时显示一圈低透明度扩散波；
- Flash 使用暖橙色效果光；
- Vibe 使用蓝紫色效果光；
- 效果光和扩散波作用于展示舱空间，不改戒指材质；
- 不使用碰撞压缩、落地阴影、撞击火花或硬碰撞音效；
- 2.6 秒自主表演结束后不再持续自转，也不进行鼠标跟随或拖拽，仅保留简单漂浮。

容器应读作太空舱或液态力场，而不是存在物理底板的盒子。

## 10. 说、触、感硬币式翻面

在“说、触、感”章节，戒指保持在正文右侧的安全展示区：

- 说 → 触：围绕屏幕水平方向的直径完成 180° 前后翻面；
- 触 → 感：沿同一方向再完成 180°；
- 翻面进度完全由 Scroll Scrub 控制；
- 向上滚动时沿原路径倒放；
- 不叠加自主翻滚；
- “触”章节只启用局部提示光，不改 `材质.005` 的基础 PBR 值。

该运动应像硬币在空中展示正反面，而不是戒指沿页面路径横向打滚。

## 11. System 与 Finale

System 位于“说、触、感”之后：

- 戒指结束硬币翻面后缩小到展示尺寸的约 40%；
- 回到页面中轴附近；
- 沿系统纵向轨道缓慢下行；
- 不遮挡系统节点与说明文字；
- 此段只由 Scroll Scrub 控制，不增加自主动画。

进入 Community CTA 时：

- 戒指回到中轴稳定产品姿态；
- 尺度适合位于 CTA 文案与二维码之间；
- 以原始黑色 PBR 材质和中性产品光结束；
- 只保留轻微漂浮，不持续翻滚。

## 12. 自主动画与滚动主轨的冲突处理

自主动画和主滚动不得写入同一个对象层：

- `JourneyRig` 可以在用户滚动时继续移动；
- `ShowcaseRig` 在当前父级坐标内完成入场、磁场减速和阻尼回弹；
- `FloatRig` 只在自主动画完成后启用；
- 离开关键展示区时，`ShowcaseRig` 和 `FloatRig` 恢复初始局部状态；
- 用户在自主动画播放期间继续滚动时，不取消动画，也不把入场偏移写回主轨；
- 快速跳过章节时允许直接进入下一主轨状态，不强制等待 2.6 秒自主表演播完。

## 13. 官网接入

Landing Page 保留一个固定全屏戒指舞台：

- 嵌入单一透明背景 Spline Viewer；
- Viewer 不承载页面文案和业务 UI；
- 页面滚轮和触控板滚动必须继续传递给文档；
- Viewer 舞台保持 `pointer-events: none`，Spline Scroll Event 只读取文档滚动，不拦截正文操作；
- 默认不启用戒指鼠标拖拽；
- Spline 加载完成前显示现有静态戒指海报；
- 加载完成后卸载海报，确保 DOM 中只有一个可见戒指；
- Spline 加载失败时保留海报，不显示空白舞台；
- Locale Provider 位于 Viewer 生命周期之外，中英文切换不能重新创建 Spline 场景。

开发期增加渲染器开关：

```text
spline | three
```

实施顺序：

1. 创建并验收 Spline 场景；
2. 在开发环境启用 Spline 路径，与当前 Three.js 路径 A/B 对照；
3. Spline 通过桌面视觉和性能验收后成为默认；
4. 现有 Three.js 运行时几何和材质改造不再进入默认官网路径；
5. 开发期开关可保留一个短周期，稳定后再决定是否删除 Three.js 路径。

Spline 场景必须创建在用户拥有的 Spline Workspace 中。实施时如需要登录，由用户在可见浏览器中完成认证；场景 URL 或导出地址写入项目配置，不把账户凭证写入仓库。

## 14. 减少动态与异常回退

`prefers-reduced-motion: reduce` 下：

- 跳过 Hero 旋转亮相；
- 跳过 Flash/Vibe 下落、回弹和旋转；
- 关闭持续漂浮；
- 说、触、感不执行连续翻面；
- 直接使用当前章节的稳定姿态；
- 如果 Spline Viewer 无法可靠暂停动画，则直接使用静态海报作为减少动态路径。

异常处理：

- 场景 URL 缺失：显示静态海报并记录开发错误；
- 场景加载超时或失败：保持海报，页面内容和 CTA 继续可用；
- WebGL 不可用：不创建 Viewer；
- 语言或页面尺寸变化：保持同一 Viewer 实例，刷新桌面滚动范围；
- 快速反向滚动：主轨倒放，自主入场子轨按展示区进入/离开规则重置。

## 15. 性能约束

- 全页只创建一个 Spline Viewer；
- 只加载一份戒指 GLB；
- 不使用多个全屏 Embed；
- 最多三盏常驻主要灯；
- 磁场扩散波使用简单几何、透明度和尺度动画；
- 不使用高数量粒子、实时布料、物理刚体或碰撞模拟；磁悬浮曲线由确定性关键帧实现；
- 不启用会降低几何精度的几何压缩；
- 记录 Spline 导出体积、首次可见时间、主线程占用和静置内存，不以视觉通过替代性能验收；
- 页面静置后不得持续创建对象、监听器或文档上下文。

## 16. 测试与验收

### 16.1 结构测试

- Landing DOM 中只存在一个实时戒指渲染器；
- Spline 路径启用时不同时挂载 Three.js Canvas；
- 加载完成前存在海报，完成后海报卸载；
- 场景失败和 WebGL 不可用时海报保留；
- 中英文切换不重建 Viewer；
- reduced-motion 路径不播放自主动画。

### 16.2 桌面视觉验收

基准视口：`1440 × 900`。

逐段检查：

- Hero 首次加载完成约 220° 产品亮相，结束后只漂浮；
- Flash 从上方进入右侧展示舱，在悬浮点附近减速、穿越、回弹并稳定；
- Vibe 从上方进入左侧展示舱，动作物理与 Flash 一致、旋转方向相反；
- Flash/Vibe 稳定后各自完成一次慢速产品旋转展示，随后只保留漂浮；
- Flash/Vibe 戒指始终不接触容器底部；
- 边界轻微滚动不会连续重复触发磁悬浮动画；
- 重新离开并进入板块时可以重播；
- 说、触、感围绕水平直径做两段 180° 翻面；
- System 出现在说、触、感之后；
- System 中戒指缩小并沿中轴下行，不遮挡文字；
- CTA 中戒指稳定停在文案和二维码之间；
- 反向滚动无瞬移、重叠或错误方向的翻面。

### 16.3 模型保真验收

- 导入前后 8 个网格节点均存在；
- 6 个材质名称和标准 PBR 基础值未被人工覆盖；
- 无网页运行时电路半径校正；
- 无替换外壳材质或人为银色过渡；
- 暖橙、蓝紫和触控效果关闭后，戒指恢复为原始黑色产品外观；
- 与原始 GLB/Blender 参考视角进行截图 A/B 对照。

### 16.4 工程与性能验收

- Landing 单元测试通过；
- TypeScript typecheck 通过；
- Vite production build 通过；
- 1440×900 浏览器完整滚动 QA 通过；
- 浏览器控制台无 Spline、WebGL 或资源加载错误；
- 场景静置前后 DOM、JS Heap、监听器和文档数量稳定；
- Spline 场景导出体积和首次可见时间被记录并与当前实现对照。

## 17. 非目标

本轮不包含：

- 移动端 Spline 轨迹与响应式编排；
- 用户拖拽、点击或鼠标跟随戒指；
- 修改原始 GLB 几何、拓扑、UV 或材质；
- 在 Spline 中承载 Landing 文案、语言切换、二维码或其他业务 UI；
- 真实刚体、液体或磁场物理模拟；
- 多个 Spline Viewer；
- 在 Spline 验收前删除现有 Three.js 开发对照路径。
