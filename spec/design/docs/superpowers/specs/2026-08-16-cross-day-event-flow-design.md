# 跨日事件时间解析与流视图设计

日期：2026-08-16  
状态：已确认，待实施计划

## 背景

戒指闪念“今天晚上 11 点到 12 点有一个线上会议”已被 ASR 正确转写，但事件整理阶段没有生成日程，只返回“有 1 项未完成”。现有 event skill 将“X 点到 Y 点”固定解释为同日，并且在没有得到 `event_id` 时统一降级为 todo，无法正确处理跨午夜时段。

本设计统一语音时间范围的向前解析语义，并让一条跨日 event 在日历流视图的所有覆盖日期中可见，同时保持唯一详情和唯一数据记录。

## 目标

- 根据语境将结束时间解析为开始时间之后最近的合理时间点。
- 正确处理“晚上 11 点到 12 点”和“晚上 11 点到 2 点”等跨午夜表达。
- 数据层始终只创建一条 event、一个 `event_id`。
- 流视图按日期展示跨日 event 的可见切片，点击任意切片进入同一个详情。
- 当事件无法生成时，向用户展示具体失败原因。

## 非目标

- 本轮不改变月视图、年视图及其他日历视图的跨日展示。
- 本轮不拆分、复制或创建影子 event 数据。
- 本轮不调整全天事件语义。
- 本轮不重做 event 详情页。

## 1. 时间解析语义

### 1.1 向前时间轴

时间范围必须先解析开始时间，再解析结束时间：

1. 根据“今天、明天、上午、下午、晚上”等语境确定绝对 `start_at`。
2. 若结束时间明确包含日期或时段，以用户明确表达为准。
3. 若结束时间只有钟点，则枚举语境允许的候选时间，选择严格晚于 `start_at` 且距离最近的候选。
4. 最终必须满足 `end_at > start_at`。

“12 点”不固定代表中午或午夜，而是由语境和向前时间轴共同决定：

| 用户表达 | 结果 |
| --- | --- |
| 上午 11 点到 12 点 | 当天 11:00–12:00 |
| 晚上 11 点到 12 点 | 当天 23:00–次日 00:00 |
| 晚上 11 点到 2 点 | 当天 23:00–次日 02:00 |
| 晚上 11 点到次日下午 2 点 | 当天 23:00–次日 14:00 |

明确说出的“次日、明天、上午、下午、晚上”优先级高于自动推断。

### 1.2 区间边界

所有 timed event 使用半开区间 `[start_at, end_at)`：

- 事件占用开始时间。
- 事件不占用结束时间这一瞬间。
- `23:00–次日 00:00` 只属于开始日期，不在次日生成可见切片。
- `23:00–次日 02:00` 同时覆盖开始日期和次日。

### 1.3 完整时段不得降级为 todo

只有单一时间点的安排才允许按现有规则降级为 todo。已经包含开始和结束范围的输入，即使 event 创建失败，也不得转成 todo；系统应保留 event 意图并返回具体错误。

## 2. 数据模型与后端职责

### 2.1 单一 event

跨日事件继续使用现有 `events` 表：

- 一个 `event_id`
- 一个 `start_at`
- 一个 `end_at`
- 一组 attendee、location、description 等详情

不增加日期切片表，不复制 attendee，也不拆分事件。

### 2.2 解析与校验分层

- event skill 负责利用原始 `source_text`、参考时间和用户时区完成语义解析。
- `tool_create_event` 负责最终数据校验，拒绝 `end_at <= start_at` 的 timed event，并返回稳定错误码 `invalid_event_range`。
- event skill 收到范围错误时，只允许基于原始语境做一次有界修正；不能静默改成 todo。
- 修正后仍不合法时，pipeline 生成 event 错误结果，并向用户展示可理解的失败原因。

### 2.3 失败反馈

失败信息必须指向实际问题，例如：

> 无法确定“线上会议”的结束时间，请补充是中午 12 点还是午夜 12 点。

不得仅展示“有 1 项未完成”。录音、ASR、事件解析和建库阶段应保持可区分状态，便于排查。

## 3. 流视图跨日投影

### 3.1 只读日期切片

现有 `CalendarData.byDay` 仅按 `TimelineItem.effectiveAt` 将记录放入开始日期。为避免影响月、年等视图，新增仅供流视图使用的日期投影层。

建议引入只读模型 `CalendarFlowSlice`：

- `eventId`：原始 event id
- `record`：原始 `CalendarRecord`
- `day`：当前切片所属日期
- `visibleStart`：该日期内的裁剪后开始时间
- `visibleEnd`：该日期内的裁剪后结束时间
- `continuesFromPreviousDay`
- `continuesIntoNextDay`

投影过程不修改原始 `TimelineItem`，也不产生可持久化对象。

### 3.2 切片规则

对事件覆盖的每个日期，以当天 `[00:00, 次日 00:00)` 与事件区间求交集：

- 交集为空：不生成切片。
- 交集非空：生成一个 `CalendarFlowSlice`。
- 结束时间等于某日 `00:00`：该日交集为空，不生成切片。

这套规则自然支持两天以上的事件，不需要增加特殊分支。

### 3.3 展示规则

以“晚上 11 点到次日 2 点的线上会议”为例：

- 第一天：`23:00–24:00　线上会议`，辅助标记“跨至明日”。
- 第二天：`00:00–02:00　线上会议`，辅助标记“承接昨日”。

两个切片保持相同标题、图标和 event 视觉身份。辅助标记使用弱化样式，不与标题争夺层级。

### 3.4 交互与计数

- 点击任意切片，均以原始 `event_id` 打开同一个 event 详情。
- 编辑开始或结束时间后，重新计算所有切片。
- 删除 event 后，所有日期中的切片同时消失。
- 流视图日期栏的当天数量包含当天可见切片。
- 资产总量和数据库统计仍按唯一 event 计数，不把切片视为多条资产。

## 4. 数据流

1. 戒指录音完成，ASR 产生原始文本。
2. flash dispatcher 将完整时间范围路由到 event skill。
3. event skill 按向前时间轴解析 `start_at` 和 `end_at`。
4. `tool_create_event` 校验并创建唯一 event。
5. timeline 继续返回唯一 `TimelineItem`。
6. Calendar 流视图在客户端将该 item 投影成一个或多个 `CalendarFlowSlice`。
7. 任一切片点击时使用相同 `event_id` 打开详情。

## 5. 测试要求

### 5.1 后端

- “上午 11 点到 12 点”解析为同日 11:00–12:00。
- “晚上 11 点到 12 点”解析为 23:00–次日 00:00。
- “晚上 11 点到 2 点”解析为 23:00–次日 02:00。
- 明确的“次日下午 2 点”不被最近时间规则覆盖。
- `tool_create_event` 拒绝 `end_at <= start_at`。
- 完整时间范围创建失败时不降级为 todo。
- 原始“线上会议”整句最终生成一条 event，并保留“小飞”“卓”和“套利策略”等信息。

### 5.2 Flutter

- `23:00–次日 00:00` 只生成一个流视图切片。
- `23:00–次日 02:00` 生成两个切片。
- 两个切片引用相同 `event_id`。
- 两个切片分别显示“跨至明日”和“承接昨日”。
- 点击任意切片打开同一个详情。
- 编辑或删除后切片集合同步刷新。
- 非跨日 event 的现有排序、分组和点击行为不回归。

## 6. 验收标准

- 用户再次说“今天晚上 11 点到 12 点有线上会议”时，系统创建一条有效 event，不再返回“有 1 项未完成”。
- 用户说“晚上 11 点到 2 点”时，流视图在两个日期中均显示该日程。
- 两处展示打开同一个详情，编辑和删除保持一致。
- 其他日历视图在本轮保持现状。
- 失败时用户能看到具体、可行动的原因。
